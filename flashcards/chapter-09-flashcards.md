## Chapter 9: Retrieval and Information Extraction Pipelines — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What are the three main retrieval strategies in Azure AI Search and when is each best? | 1) Vector search (cosine similarity): pure semantic search, best for natural language queries. 2) Hybrid search (vector + keyword): combines semantic + exact matching, best for production RAG — handles both meaning and specific terms. 3) Semantic ranking: re-ranks hybrid results using deep learning, best quality but adds latency. Exam tip: Hybrid + semantic ranking is the recommended pattern for RAG systems. |
| 2 | Azure AI Search HNSW algorithm: what is it and why use it? | HNSW (Hierarchical Navigable Small World) is an approximate nearest neighbor algorithm for vector search. Provides 95-99% recall with 10-100x faster queries than exhaustive search. Default for vector fields in Azure AI Search. Exam tip: Enable HNSW for production vector search — exhaustive search doesn't scale beyond 10,000 vectors. |
| 3 | What is skillset caching in Azure AI Search and when does it save cost? | Skillset caching stores enrichment results (OCR, entity extraction, etc.) in Azure Storage. If a document hasn't changed, cached results are reused instead of re-running expensive skills. Saves 50-90% of enrichment costs for re-indexing scenarios. Exam tip: Always enable skillset caching for production pipelines — it's in the indexer configuration. |
| 4 | Optimal RAG chunk size and overlap configuration? | Chunk size: 512-1024 tokens for most scenarios. Overlap: 50-100 tokens (10-20% of chunk size). Use semantic chunking (paragraph/section boundaries) not fixed token counts. Include parent document metadata in each chunk. Exam tip: Fixed token chunking causes mid-paragraph splits — semantic chunking preserves context. |
| 5 | Azure Content Understanding vs Azure AI Document Intelligence: when to use each? | Content Understanding: multimodal documents where images/charts carry semantic meaning (research papers, reports). Single unified model for text + images + layout. Document Intelligence: structured forms, invoices, contracts. Prebuilt models for common document types. Better for fixed layouts and key-value extraction. Exam tip: Content Understanding = multimodal semantics. Document Intelligence = structured extraction. |
| 6 | What built-in skills are available in Azure AI Search enrichment pipelines? | OCR (text from images), entity recognition (people, places, orgs), key phrase extraction, language detection, sentiment analysis, image analysis (tags, captions), PII detection, custom skills (Azure Functions). Exam tip: Built-in skills run in-process (fast). Custom skills use HTTP calls (add latency). |
| 7 | Azure AI Search index: how to configure fields for hybrid search? | Vector fields: type=Collection(Edm.Single), dimensions=1536 (for text-embedding-3-small), algorithm=HNSW. Text fields: type=Edm.String, searchable=true, filterable=true (for filters). Enable semantic configuration for ranking. Exam tip: Hybrid search requires BOTH vector and text fields in the index schema. |
| 8 | How to reduce Azure AI Search enrichment pipeline costs? | 1) Enable skillset caching. 2) Reduce OCR DPI (150 vs 300). 3) Use larger batch sizes. 4) Remove unnecessary skills (e.g., language detection if single language). 5) Use built-in skills over custom skills when possible. Exam tip: Skillset caching is the #1 cost saver — can reduce costs by 50-90%. |
| 9 | Azure AI Document Intelligence: prebuilt layout model vs prebuilt contract model? | Layout model: extracts text, tables, selection marks, structure (pages, sections). Generic for any document. Contract model: extracts layout PLUS contract-specific entities (parties, dates, amounts, clauses). Purpose-built for legal contracts. Exam tip: Use prebuilt models when available (contract, invoice, receipt) — higher accuracy than layout + custom parsing. |
| 10 | What is semantic ranking in Azure AI Search and when does it help? | Semantic ranking re-ranks search results using deep learning models that understand meaning, not just keywords. Applied after initial hybrid search retrieval (top 50 results). Improves relevance for natural language queries. Adds 50-200ms latency. Exam tip: Semantic ranking is optional but recommended for RAG — it's configured in the search index, not per query. |
| 11 | How to handle outdated information in RAG knowledge bases? | Add timestamp field to documents. Filter queries by recency (last 30/90 days). Use semantic ranking to prioritize recent content. Implement document versioning. Set up scheduled re-indexing for updated docs. Exam tip: Timestamp filtering prevents agents from citing outdated data — critical for compliance scenarios. |
| 12 | Azure AI Search: what is the maximum k value for vector search and typical production value? | Maximum k: typically 1000 (depends on service tier). Production k for RAG: 10-20. Only top 3-5 chunks are passed to LLM. Higher k increases latency without quality gain. Exam tip: k=50 is overkill for most RAG scenarios — reduce to 10 for faster queries. |
