## Chapter 2: Monitoring, Securing, and Responsible AI Controls — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What are the three Azure AI safety layers and when to use each: content filters, prompt shields, custom blocklists? | Content filters: detect harmful content in inputs/outputs (violence, hate, sexual, self-harm) — severity 0-6. Prompt shields: detect prompt injection attacks (direct/indirect) — protect system prompts. Custom blocklists: block known specific terms/patterns — static keyword lists. Exam tip: Prompt injection = prompt shields, harmful content = filters, known bad words = blocklist. |
| 2 | Azure OpenAI quota enforcement: per-minute quota vs burst limit? | Per-minute quota: max tokens per minute (TPM) for sustained load. Burst limit: max tokens per 10 seconds (~20% of per-minute quota). Both enforced simultaneously. Exam tip: 429 errors during bursts despite low average usage = hitting burst limit, not per-minute quota. |
| 3 | Content filter severity levels: what do levels 0-6 mean? | 0-6 scale where lower = stricter filtering. Level 0: blocks almost everything. Level 2: default (recommended balance). Level 6: blocks only extreme violations. Exam tip: Increase level number (e.g. 2→4) to allow more content through (reduce false positives). Decrease to be stricter. |
| 4 | RAG grounding metrics: groundedness vs relevance vs provenance? | Groundedness: is the answer supported by retrieved docs (detects fabrication). Relevance: do retrieved docs match the query. Provenance: metadata showing which doc each answer part came from. Exam tip: Fabrication/hallucination in RAG = groundedness metric, not relevance. |
| 5 | Agent oversight modes: autonomous vs semiautonomous? | Autonomous: agent executes all tool calls without human approval. Semiautonomous: agent proposes actions, waits for human approval based on configurable rules (e.g. transaction amount, sensitivity). Exam tip: Need approval workflows = semiautonomous mode. |
| 6 | Azure OpenAI keyless authentication: how does it work? | Use Azure AD managed identity + RBAC roles instead of API keys. Application authenticates using identity, no keys to store/rotate. Role: 'Cognitive Services OpenAI User' for read/inference. Exam tip: 'No keys in code' requirement = managed identity, not Key Vault (which still uses keys). |
| 7 | What indicates model drift in Azure OpenAI monitoring? | Latency increases for identical prompts over time. Output quality degradation. Changing token usage patterns without code changes. Exam tip: Drift = temporal performance/quality changes, not one-time spikes. Solution: redeploy model or update to newer version. |
| 8 | Prompt shields: direct vs indirect attack detection? | Direct attacks: user prompt tries to override system ('ignore instructions'). Indirect attacks: malicious content in retrieved docs/tools tries to manipulate model. Both blocked by prompt shields. Exam tip: RAG with untrusted docs = enable indirect attack protection. |
| 9 | Azure OpenAI private endpoints: what do they secure? | Network access to Azure OpenAI resource — traffic never leaves Microsoft backbone. Deployed in your VNet. Exam tip: Private endpoints = network security, NOT authentication (still need keys or managed identity for API auth). Combine with keyless for full security. |
| 10 | Agent tool-access controls: what can they enforce? | Which tools agent can use. Pre-execution hooks (e.g. logging before execution). Post-execution validation. Rate limits per tool. Exam tip: 'Must log before execution' = pre-execution hook in tool-access controls, not approval workflow. |
| 11 | Content filter violation monitoring: what triggers a safety event? | Input or output exceeds configured severity threshold for any category (violence, hate, sexual, self-harm). Jailbreak attempt detected. Prompt shield blocks injection. Logged as safety event for monitoring. Exam tip: Track violation patterns to tune severity thresholds. |
| 12 | Azure OpenAI token usage analytics: what to monitor for cost optimization? | Tokens per request (prompt + completion). TPM utilization vs quota. Most expensive endpoints/users. Prompt efficiency (same output with fewer tokens). Exam tip: High TPM usage near quota = throttling risk. Optimize prompts or request quota increase. |
