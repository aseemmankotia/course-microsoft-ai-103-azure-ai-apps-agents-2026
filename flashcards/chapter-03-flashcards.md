## Chapter 3: Building Generative Applications with Foundry — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | RAG vs Fine-tuning: When to use each for domain knowledge? | RAG: Dynamic knowledge that changes frequently, factual QA, citations needed. Updates in minutes (re-index). Fine-tuning: Task behavior, writing style, output format. Updates require retraining (hours/days). Exam rule: RAG for facts, fine-tuning for behavior. |
| 2 | Azure AI Foundry SDK: Code to create chat completion with streaming? | client.complete(messages=[...], stream=True) for chunk in response:     print(chunk.choices[0].delta.content) Exam tip: stream=True parameter enables streaming. Final chunk contains usage metadata (total_tokens). |
| 3 | Temperature parameter: Range and effect on output? | Range: 0 to 2. 0=deterministic/focused, 1=balanced, 2=very random. Exam defaults: 0.7 for creative tasks, 0.2 for factual/structured. Exam trap: temperature does NOT control factuality, only randomness. |
| 4 | Chain-of-thought prompting: Required components? | 1) Instruction to show reasoning ('think step-by-step'), 2) Prompt structure inviting reasoning ('Let's solve this'). Optional: few-shot CoT examples. Exam tip: CoT is about reasoning PROCESS, not answer accuracy. |
| 5 | Function calling (tools): When is model.tool_calls populated? | When model determines it needs external data/action. Model returns tool_calls instead of content. App executes function, adds result to messages, calls model again. Exam tip: model decides when to call, app executes. |
| 6 | Hybrid retrieval in Azure AI Search: What are the two methods combined? | Vector search (semantic similarity via embeddings) + Keyword search (BM25 full-text). Combined with RRF (Reciprocal Rank Fusion). Exam tip: Hybrid = best of both, handles exact matches AND semantic queries. |
| 7 | Frequency_penalty and presence_penalty: Range and purpose? | Range: 0 to 2. Frequency: penalizes tokens based on count (reduces repetition). Presence: penalizes tokens if they appeared at all (encourages topic diversity). Typical: 0.5-1.0. Exam trap: 2.0 is max, often too high. |
| 8 | Fabrication detection in RAG: Primary mitigation technique? | System message grounding: 'Answer ONLY using provided context. Cite chunk IDs. If not in context, say I don't know.' Exam pattern: Explicit constraints > parameter tuning. Temperature=0 doesn't prevent fabrication. |
| 9 | Few-shot prompting: Structure and purpose? | System: [role]. User: [Example 1 Q+A, Example 2 Q+A, ...] Now: [actual query]. Purpose: Demonstrate task format/style, not provide knowledge. Exam tip: 2-5 examples typical. Limited by context window. |
| 10 | Top_p (nucleus sampling): Range and interaction with temperature? | Range: 0 to 1. Selects from top tokens whose cumulative probability ≥ top_p. Exam: Use temperature OR top_p, not both. Default: top_p=1 (disabled) when using temperature. Typical: 0.9-0.95 for diversity. |
| 11 | LLM-as-judge evaluation: What three qualities are typically scored? | Relevance (1-5): answer matches question. Coherence (1-5): logical flow, no contradictions. Fabrication (yes/no): unsupported claims. Exam tip: Use GPT-4 as judge + human spot-checks (10%). Current best practice for scale. |
| 12 | Foundry SDK tracing: What data is automatically captured? | Prompts (all messages), completions (responses), token counts (prompt + completion + total), latency, model parameters (temp, top_p, etc.), timestamps. Exam tip: Built-in observability, no custom code needed. |
