## Chapter 5: Optimizing and Operationalizing Generative Solutions — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Azure OpenAI temperature parameter range and effect at extremes | Range: 0.0 to 2.0. At 0.0: deterministic, repeatable, factual (use for extraction, classification). At 2.0: maximum randomness, creative but risky (use for brainstorming only). Exam tip: Customer service/legal = 0-0.3, Creative writing = 0.7-1.0 |
| 2 | Difference: frequency_penalty vs presence_penalty | frequency_penalty: penalizes tokens based on HOW MANY TIMES they appeared (reduces repetition within response). presence_penalty: penalizes tokens based on WHETHER they appeared at all (encourages topic diversity). Exam tip: Repeated words = frequency_penalty. Same topic repeatedly = presence_penalty. |
| 3 | top_p (nucleus sampling) — what value and use case? | Range: 0.0 to 1.0. Controls token selection pool by cumulative probability. 0.1 = only top 10% most likely tokens (very focused). 0.9 = top 90% tokens (balanced). 1.0 = all tokens considered. Exam tip: Use top_p OR temperature, not both at extreme values. |
| 4 | Azure OpenAI GPT-4 token costs (2026) | Prompt tokens: $0.03 per 1K. Completion tokens: $0.06 per 1K (2x prompt cost). Exam tip: Completion tokens cost MORE because generation is more compute-intensive. Optimize by reducing completion length or caching prompts. |
| 5 | Hybrid architecture pattern: LLM + rules engine — when to use? | Use when: deterministic validation required (legal, medical, financial), hard constraints must be enforced, 99%+ accuracy needed. Rules engine validates LLM output against database/protocols. Exam tip: High-stakes decisions always need deterministic layer, not just LLM. |
| 6 | Prompt engineering: role-based prompting syntax and purpose | Syntax: 'You are a [specific expert role]. [Task with constraints].' Purpose: Establishes response style and expertise level. Example: 'You are a Python security expert. Review this code for vulnerabilities.' Exam tip: Always include specific role, not generic 'assistant'. |
| 7 | Token optimization: prompt caching vs semantic caching difference | Prompt caching: Azure caches identical prompt prefixes to skip reprocessing (saves prompt token costs). Semantic caching: Application caches similar query responses (saves entire API call). Exam tip: Prompt caching = same prompt, semantic caching = similar meaning. |
| 8 | Latency breakdown in RAG: typical bottleneck and optimization | Typical breakdown: Retrieval 20%, Prompt processing 30%, Generation 50%. Bottleneck: Usually generation due to token count. Optimization: Reduce retrieved documents (cuts prompt processing AND generation context). Exam tip: Fewer documents = faster prompt + generation, not just retrieval. |
| 9 | Chain-of-thought prompting — syntax and exam use case | Syntax: 'Let's think step by step:' or 'Show your reasoning before the final answer.' Use case: Complex reasoning tasks (math, logic, multi-step problems). Exam tip: Improves accuracy for reasoning but increases token cost (longer completions). Not for simple tasks. |
| 10 | Multi-model orchestration pattern: small model + large model roles | Small model (e.g., BERT, fine-tuned classifier): Fast classification, high precision on specific task, low cost. Large model (e.g., GPT-4): Broad understanding, complex reasoning, high cost. Exam tip: Classify with small, generate with large. Never use GPT-4 for simple classification alone. |
| 11 | Negative prompting technique and example | Technique: Explicitly state what NOT to include in output. Example: 'Write a summary. Do not include opinions, speculation, or information not in the source text.' Exam tip: Use for factual accuracy, avoiding hallucinations, or content filtering. |
| 12 | Confidence threshold in hybrid architectures — purpose and typical range | Purpose: Set minimum confidence score before accepting LLM output; below threshold triggers fallback logic (rules engine, human review, safer model). Typical range: 0.7-0.9 for high-stakes decisions. Exam tip: Medical/legal/financial systems always use confidence thresholds + fallbacks. |
