## Chapter 4: Building Agents with Microsoft Foundry — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Agent tool schema required JSON fields for function calling? | name, description, parameters (JSON Schema). Exam tip: 'description' is critical — agent uses it to decide when to call the tool. Poor descriptions = wrong tool selection. |
| 2 | Difference between autonomous vs semiautonomous agent mode? | Autonomous: agent executes all functions without human approval. Semiautonomous: agent requests approval before executing flagged functions (high-risk operations). Exam tip: DELETE, financial transactions = semiautonomous. |
| 3 | Four memory types for agents and when to use each? | 1) Conversation history: full verbatim log (short conversations). 2) Summary memory: condensed summaries (long conversations). 3) Entity memory: structured data extraction (tracking people/dates/IDs). 4) Vector memory: semantic search over past conversations (knowledge retrieval). Exam tip: Summary memory most tested for token-limited long conversations. |
| 4 | Sequential vs parallel orchestration — key difference? | Sequential: Agent B receives Agent A's output as input (dependent workflow). Parallel: Multiple agents execute simultaneously with same input (independent tasks). Exam tip: If one agent's output feeds another = sequential. If tasks are independent = parallel. |
| 5 | Tool-access controls vs conversation boundaries — what's the difference? | Tool-access controls: permission checks before executing functions (role-based security). Conversation boundaries: define allowed topics/domains agent can discuss (content filtering). Exam tip: Data security = tool-access controls. Topic restrictions = boundaries. |
| 6 | Agent evaluation metric: tool usage accuracy measures what? | Percentage of tasks where agent selected the correct tool(s) for the job. Example: 80% tool usage accuracy = agent used right tool 8 out of 10 times. Exam tip: High task completion + low tool accuracy = agent completes tasks but uses wrong methods (brute force vs elegant solution). |
| 7 | Function calling parameter schema — what happens if parameter is missing? | Agent will ask user for the missing parameter before calling function. If parameter marked 'required: true' in schema, agent MUST obtain it. If optional, agent proceeds without it. Exam tip: Required parameters = agent asks follow-up questions. |
| 8 | Hierarchical multi-agent pattern — when to use it? | When specialist agents need to spawn their own sub-agents for subtasks. Example: Legal agent spawns Contract agent + Compliance agent. Exam tip: Rarely correct answer — most scenarios use coordinator + specialists (flat hierarchy). Hierarchical = complex nested workflows only. |
| 9 | Conversation coherence in agent evaluation — what does it measure? | Quality of multi-turn dialogue: does agent maintain context, avoid repetition, reference earlier messages correctly? Scored 0-1. Exam tip: Low coherence = memory/context issue. High task completion + low coherence = agent succeeds but conversations feel disjointed. |
| 10 | Azure AI Search tool vs RAG pattern for agents — key difference? | Azure AI Search tool: agent calls search as external function (tool calling). RAG pattern: search integrated into agent's retrieval pipeline (automatic grounding). Exam tip: Tool calling = agent decides when to search. RAG = always grounds responses in indexed data. |
| 11 | Code execution capability in agents — what security consideration is tested? | Sandboxed environment required to prevent arbitrary code execution risks. Agent generates code (Python), executes in isolated container, returns output. Exam tip: Never allow direct system-level code execution. Always sandbox + timeout limits. |
| 12 | Coordinator agent failure handling — best practice for specialist agent errors? | Implement graceful degradation: return partial results from successful agents + error message about failed agent. Don't block entire response on one failure. Exam tip: In parallel orchestration, set wait_for_all: false to allow partial success. |
