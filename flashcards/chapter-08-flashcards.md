## Chapter 8: Text Analysis and Speech Solutions — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Azure OpenAI JSON schema enforcement — what parameter and what does it guarantee? | response_format parameter with json_schema type. Guarantees the response matches your exact JSON schema structure, including required fields and data types. Exam tip: Use this for structured output extraction (entities, forms, compliance data) instead of traditional NER when you need guaranteed field presence and validation. |
| 2 | Speech agent modality — what are the three core components for a voice AI agent? | 1) Azure AI Speech (speech-to-text) for input, 2) Azure OpenAI (reasoning/response generation), 3) Azure AI Speech (text-to-speech) for output. Exam tip: This is the standard pattern. Don't use LUIS (deprecated) or translate if the LLM is multilingual. |
| 3 | Azure Translator custom models vs Azure OpenAI for translation — when to use which? | Use Azure Translator custom models for: high-volume (10K+ docs), domain-specific terminology, guaranteed consistency. Use Azure OpenAI for: context-aware translation, low volume, nuanced/creative translation. Exam tip: Custom Translator is more cost-effective at scale and has terminology dictionaries for consistency. |
| 4 | Azure AI Content Safety — what harmful content categories does it detect? | Hate, sexual, violence, self-harm. Returns severity scores 0-7 for each category. Exam tip: Use Content Safety API for safety detection, not sentiment analysis. Sentiment detects positive/negative/neutral tone, not safety violations. |
| 5 | Azure AI Speech batch transcription vs real-time transcription — cost and use case difference? | Batch: cheaper, for pre-recorded audio, asynchronous (submit file, get results later). Real-time: more expensive, for live audio, synchronous streaming. Exam tip: For 1000+ pre-recorded calls, always use batch transcription. Real-time is for live conversations or agents. |
| 6 | Azure AI Speech custom speech model — what are the two customization types? | 1) Acoustic model customization (audio training data with transcripts), 2) Language model customization (phrase lists and text corpus). Exam tip: Use custom speech for domain-specific terminology (medical, legal) or non-standard accents. Phrase lists boost recognition of specific terms. |
| 7 | Azure OpenAI multilingual capability — does GPT-4 require translation before processing non-English text? | No. GPT-4 and GPT-4o are multilingual (50+ languages) — they understand and respond in the input language natively. Exam tip: Don't add Azure Translator before/after OpenAI for multilingual support. Translation adds latency and degrades quality. The LLM handles it directly. |
| 8 | Structured JSON output from Azure OpenAI — how to enforce required fields? | In the JSON schema, specify 'required': ['field1', 'field2']. The API will ensure these fields are present in the response. Exam tip: This is better than post-validation because the model must populate required fields or the call fails — guarantees completeness. |
| 9 | Azure AI Speech phrase list — what is it and when to use it? | A list of domain-specific terms (product names, medical terms, jargon) that boosts speech recognition accuracy for those terms. Used with both standard and custom speech models. Exam tip: Phrase lists are the quick fix for specialized vocabulary without full custom model training. |
| 10 | Traditional NER vs LLM entity extraction — key difference for structured output? | Traditional NER: finds entities but doesn't guarantee structure or field validation. LLM with JSON schema: extracts entities AND enforces structure/validation in one step. Exam tip: For unstructured text to structured database, use LLM with JSON schema, not NER + post-processing. |
| 11 | Azure AI Speech language detection — automatic or manual configuration? | Both supported. Auto language detection: specify candidate languages, the service detects which is spoken. Manual: specify exact language code. Exam tip: For multilingual support, use auto-detect with candidate list. For known single language, manual is slightly faster. |
| 12 | Speech translation workflow — Azure Translator vs Azure AI Speech translation vs LLM translation? | Azure AI Speech: real-time speech translation (audio in language A → text in language B). Azure Translator: text-to-text, batch or real-time, custom models. LLM: text translation with context. Exam tip: For live audio translation, use AI Speech. For text translation at scale with consistency, use Translator custom models. |
