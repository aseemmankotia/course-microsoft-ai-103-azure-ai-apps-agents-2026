## Chapter 1: Planning and Managing Azure AI Solutions — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | PTU (Provisioned Throughput Unit) cost structure and when to use vs serverless | 1 PTU ≈ $300-600/month depending on model. Break-even: ~1M tokens/day sustained usage. Use PTUs for: predictable high throughput (>100 req/min sustained), latency SLA requirements, cost certainty. Serverless for: variable/bursty workloads, development, <500K tokens/day. Exam tip: PTU questions test cost calculation vs usage patterns. |
| 2 | Hybrid search vs vector search vs keyword search in Azure AI Search | Vector: semantic similarity, best for conceptual queries. Keyword (BM25): exact term matching, best for technical/legal terms. Hybrid: combines both with RRF (Reciprocal Rank Fusion). Exam rule: temporal queries + technical docs = hybrid with semantic ranker. Pure vector misses exact terminology; pure keyword misses synonyms. |
| 3 | DefaultAzureCredential authentication chain order | Order: 1) EnvironmentCredential, 2) ManagedIdentityCredential, 3) AzureCliCredential, 4) Others. In production (Azure-hosted): uses managed identity. In local dev: uses Azure CLI login. Exam tip: keyless authentication = managed identity. No secrets in code/config. Most tested auth pattern for Azure AI services. |
| 4 | Azure AI Foundry hub vs project isolation model | Hub: shared resources (compute, networking, identities, quotas). Project: workspace isolation within hub (separate deployments, experiments, endpoints). Network isolation: managed VNet at hub level, NSG rules per project. Exam gotcha: cannot create private endpoint per project — it's hub-level. Projects inherit hub networking. |
| 5 | GPT-4o vs GPT-4o mini vs Phi-3 model selection criteria | GPT-4o: complex reasoning, vision tasks, $2.50/$10 per 1M tokens (in/out). GPT-4o mini: simple queries, high volume, $0.15/$0.60 per 1M tokens — 15x cheaper. Phi-3 (3.8B): on-device/edge, $0.10 per 1M, lacks vision. Exam pattern: cost-sensitive + high volume + simple queries = mini. Vision required = GPT-4o. |
| 6 | Semantic ranker configuration and when to apply | L1 (free): re-ranks top 50 results. L2 (paid): top 2500 results. Adds ~50-300ms latency. Use for: RAG quality improvement, temporal relevance boosting, multi-field ranking. Skip for: latency-critical apps, keyword-only search. Exam tip: hybrid search + semantic ranker = most tested RAG pattern for production. |
| 7 | Azure OpenAI quota types: TPM, RPM, PTU limits | TPM (Tokens Per Minute): serverless throughput limit, e.g. 10K-240K depending on region/model. RPM (Requests Per Minute): max 300-6000 depending on tier. PTU: fixed capacity unit, no TPM/RPM limits but fixed cost. Exam gotcha: TPM quota != guaranteed throughput in serverless. Rate limit errors hit TPM then RPM. |
| 8 | Function calling in Azure OpenAI agent workflows | Pattern: define tool JSON schema → model decides when to call → execute function → return result to model. Not actual function execution by model — model returns structured request, you call function. Exam tip: function calling enables agents to use external tools (APIs, databases). Tool = any external capability accessed during reasoning. |
| 9 | Managed identity: system-assigned vs user-assigned for AI services | System-assigned: tied to resource lifecycle, auto-deleted with resource, 1:1 relationship. User-assigned: independent lifecycle, reusable across resources, persists after resource deletion. Exam rule: single app/service = system-assigned (simpler). Shared identity across multiple resources = user-assigned. Most questions test system-assigned. |
| 10 | Vector index rebuild vs refresh in Azure AI Search | Rebuild: full re-indexing, drops and recreates index, downtime possible. Refresh: incremental update, adds/updates/deletes docs, no downtime. Exam scenario: schema changes (new fields, vectorizer change) = rebuild required. New documents only = refresh sufficient. Rebuild cost: full re-embedding of all docs. |
| 11 | Azure AI Foundry deployment environment promotion pattern | Pattern: dev project → staging project → prod project, all in same hub OR separate hubs. Use model registry for versioning. Deployment gate: validate metrics (accuracy, latency) before prod. Blue/green: maintain N-1 version for rollback. Exam tip: approval gates query model registry metadata — don't re-run validation in gate. |
| 12 | Token budget management for cost control in agent applications | Strategies: max_tokens per request (hard limit), token counting middleware (track/alert), prompt compression (reduce input tokens), response streaming (partial results). Exam calculation: 1M tokens ≈ 750K words. Budget $100/day with GPT-4o ($2.50 per 1M input) = 40M tokens/day max = ~53K tokens/min sustained. |
